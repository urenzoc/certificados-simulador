1. Código para procesamiento con Python y SQL

23% del examen

Pipelines declarativos, streaming con estado, jobs, UDF, pruebas y cómputo.

Lakeflow Declarative Pipelines (antes DLT)

Streaming tableMaterialized view
ProcesaSolo datos nuevos (append), incrementalRecalcula el resultado (incremental cuando puede)
Ideal paraIngesta de baja latencia, fuentes que solo crecenAgregaciones, joins, datos que se actualizan o borran
CostoBajo por eventoMayor si recalcula mucho
CREATE OR REFRESH STREAMING TABLE silver_clientes;
CREATE FLOW f AS AUTO CDC INTO silver_clientes
FROM STREAM(bronze_cdc)
KEYS (id)
APPLY AS DELETE WHEN op = "D"
SEQUENCE BY ts
STORED AS SCD TYPE 2;
  • AUTO CDC (antes APPLY CHANGES): aplica cambios en orden con SEQUENCE BY, maneja desorden y borrados. SCD 1 sobrescribe; SCD 2 guarda historial con __START_AT/__END_AT.
  • Structured Streaming vs. Declarative Pipelines: el primero da control total (foreachBatch, lógica custom); el segundo gestiona dependencias, calidad, reintentos y escalado automáticamente.

Streaming con estado

  • Watermark limita cuánto esperar datos tardíos y permite limpiar estado.
  • Modos de salida append/update/complete; foreachBatch para escribir cada micro-lote con lógica arbitraria (MERGE, varios destinos).
  • Checkpoint por consulta; no compartirlo entre streams.

Jobs, UDF, dependencias y pruebas

  • Lakeflow Jobs por UI, REST API, CLI o bundles; control de flujo If/Else y For Each.
  • UDF: Python, Pandas (vectorizadas, más rápidas) y SQL; funciones de Unity Catalog reutilizables y gobernadas.
  • Dependencias: entornos serverless (environment con versiones fijadas), librerías de clúster/notebook (%pip), wheels en volúmenes; resolver conflictos fijando versiones.
  • Cómputo: serverless con modo de rendimiento vs. estándar (costo), tareas de notebook de alta memoria.
  • Pruebas: pyspark.testing.assertDataFrameEqual, assertSchemaEqual; funciones puras encadenadas con DataFrame.transform para testear unitariamente; pytest.

Trampas frecuentes

  • Streaming table no maneja bien updates/deletes de la fuente; usa AUTO CDC o materialized view.
  • SCD 2 conserva historial; SCD 1 no.

  • Pipelines CDC incrementales con destino Delta o Iceberg.

3. Manipulación de datos

12% del examen

Ventanas, semiestructurados, funciones de IA y calidad.

  • Ventanas: ROW_NUMBER, RANK, LAG/LEAD, sumas acumuladas con ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW.
  • Deduplicar el último registro por clave: QUALIFY ROW_NUMBER() OVER (PARTITION BY id ORDER BY ts DESC) = 1.
  • VARIANT: parse_json(col), variant_get(v, '$.a.b', 'int'), notación v:a.b::int.
  • Funciones de IA: ai_query('endpoint', prompt), ai_classify, ai_extract, ai_summarize en pipelines por lotes.
  • Expectations: registrar (EXPECT), descartar (DROP ROW), fallar (FAIL UPDATE); cuarentena = enrutar inválidos a otra tabla con la condición inversa.

15% del examen

Layout de datos y mantenimiento automático.

Trampas frecuentes

  • No combines particionamiento ni ZORDER con Liquid Clustering.
  • skipChangeCommits ignora cambios; CDF los procesa.

6. Seguridad y cumplimiento

8% del examen

Mínimo privilegio, ABAC, anonimización y purga.

  • ACL de mínimo privilegio en objetos de UC y recursos del workspace (clústeres, jobs, notebooks).
  • ABAC con etiquetas gobernadas: una política aplica filtros de fila y máscaras de columna a todas las tablas etiquetadas.
  • Anonimización (irreversible: supresión, generalización) vs. seudonimización (reversible o enlazable: hashing con sal, tokenización).
  • Detectar y enmascarar PII en batch y streaming.
  • Purga (RGPD): DELETE + VACUUM para eliminar físicamente; con deletion vectors hace falta REORG TABLE … APPLY (PURGE) antes de VACUUM.

7. Gobernanza de datos

5% del examen

Metadatos y herencia de permisos.

  • COMMENT ON TABLE, comentarios de columnas y etiquetas para descubrimiento (y comentarios generados por IA).
  • Herencia: un permiso en catálogo aplica a sus esquemas y tablas presentes y futuras; USE CATALOG/USE SCHEMA son requisito para acceder.

8. Depuración y despliegue

10% del examen

Diagnóstico, reparación y CI/CD.

  • Diagnóstico con Spark UI, logs del clúster, system tables y Query Profile.
  • Repair run con sobrescritura de parámetros para reejecutar solo lo fallido.
  • Declarative Automation Bundles (antes Databricks Asset Bundles): databricks.yml, targets, variables; bundle validate/deploy/run.
  • CI/CD con Git folders y pipelines (GitHub Actions, Azure DevOps) que despliegan bundles con service principals.

9. Modelado de datos

5% del examen

Diseño de tablas y modelos dimensionales.

  • Diseño de tablas Delta/Iceberg: particionar por grano solo cuando conviene, clustering según patrones de acceso, compactación para archivos equilibrados.
  • Modelos dimensionales: hechos y dimensiones; SCD 2 para dimensiones históricas.
  • Materialized views para agregados precalculados y metric views de Unity Catalog para definiciones de métricas gobernadas y reutilizables.
Glosario rápido (64 términos)
Alertas
Alertas sobre el valor de una consulta; destinos correo, Slack, Teams y webhook; plantillas personalizadas.
APPLY CHANGES INTO
Aplica feeds CDC en DLT, ordenando con SEQUENCE BY.
Auto Loader
Ingesta incremental de archivos nuevos con Structured Streaming; schemaLocation, evolución de esquema y file notification.
Auto Optimize
Optimized Writes + Auto Compaction: compactan durante las escrituras hacia ~128 MB, sin Z-Order.
Bronze
Capa de datos sin procesar con el historial completo.
Change Data Feed
Registra cambios fila a fila (_change_type); útil cuando cambia una fracción pequeña de registros.
Checkpoint
Guarda el progreso y estado del stream; da tolerancia a fallos y no se comparte entre streams.
CLONE
DEEP CLONE copia datos y metadatos; SHALLOW CLONE solo referencia los archivos de la fuente.
Cluster pools
Instancias inactivas listas que reducen el tiempo de inicio del clúster.
Clúster all-purpose
Clúster interactivo para desarrollo y análisis; más caro que un job cluster.
Columna generada
GENERATED ALWAYS AS (expr): Delta calcula el valor automáticamente.
Comandos mágicos
%python/%sql/%scala/%r cambian el lenguaje de la celda; %sh corre solo en el driver; %pip instala librerías del notebook; %run incluye otro notebook.
Control plane / data plane
Control plane: app web, notebooks, jobs y consultas en la cuenta de Databricks. Data plane: VM del clúster y datos en la cuenta cloud del cliente.
COPY INTO
Carga idempotente de archivos con SQL: omite los que ya se cargaron.
Cron
Expresión para programaciones complejas de jobs.
CTAS / INSERT OVERWRITE
CTAS reemplaza datos y esquema; INSERT OVERWRITE reemplaza solo datos. Ambos conservan el historial.
Dashboards SQL
Varias visualizaciones por consulta, parámetros de filtro, refresco programado y Query History/profile.
Data Explorer
Interfaz para explorar datos y gestionar permisos sobre tablas.
Data skipping
Delta usa min/max por archivo (primeras 32 columnas, en el log) para saltar archivos.
Databricks Repos
Carpetas Git: clone, pull, commit/push, ramas y diffs. Pull requests, aprobación y borrar ramas se hacen en el proveedor Git.
DBFS
Databricks File System: abstracción sobre el almacenamiento de objetos con rutas tipo Unix.
dbutils
Utilidades: widgets (parámetros), notebook.run, secrets.get (se muestra REDACTED), fs.
Delta Lake
Formato abierto: Parquet + log JSON (_delta_log) con ACID, time travel y evolución de esquema.
Delta Live Tables
Pipelines declarativos con tablas LIVE/STREAMING, expectativas y modos Triggered/Continuous.
Delta Sharing
Protocolo abierto para compartir datos con otras organizaciones y plataformas.
DESCRIBE HISTORY / DETAIL / EXTENDED
HISTORY: versiones y quién cambió. DETAIL: ubicación y archivos. EXTENDED: tipo de tabla, propiedades, restricciones y comentarios.
Expectativas DLT
Sin ON VIOLATION: conserva y reporta. DROP ROW: descarta y reporta. FAIL UPDATE: detiene el pipeline.
from_json
Convierte un string JSON en struct; requiere el esquema.
Funciones de arrays
explode: una fila por elemento. flatten: aplana arrays anidados. collect_set: valores únicos. FILTER/TRANSFORM: funciones de orden superior con lambdas.
Gold
Capa de agregados de negocio optimizada para consultas, dashboards y ML.
GRANT / privilegios
GRANT priv ON TABLE t TO principal. MODIFY = agregar/borrar/modificar; USAGE es requisito para acceder a objetos del schema.
Job cluster
Clúster que se crea para un job y termina al finalizar; recomendado para producción.
Jobs / Workflows
Orquestan tareas con dependencias, clústeres por tarea, parámetros, reintentos y notificaciones.
Lakehouse
Une data lake y data warehouse: formatos abiertos, ACID, BI y ML, streaming y batch, esquema impuesto y evolutivo.
MERGE INTO
Inserta, actualiza o elimina según coincidencias; evita duplicados.
MLflow UDF
mlflow.pyfunc.spark_udf(spark, model_uri) registra un modelo como UDF de Spark.
Modos de salida
append (solo filas nuevas), complete (reescribe todo el resultado), update.
Modos DLT
Triggered: una vez. Continuous: siempre. Development: reutiliza el clúster. Production: reintenta y termina el clúster.
OPTIMIZE / ZORDER
OPTIMIZE compacta archivos pequeños; ZORDER BY agrupa valores de columnas de filtro para data skipping.
Particionamiento
Particionar por columnas de baja cardinalidad (p. ej. fecha); el sobreparticionado degrada el rendimiento.
Permisos de clúster
Can Attach To: ver métricas/Spark UI. Can Restart: iniciar/terminar. Can Manage: editar configuración.
Propiedad (owner)
El creador es dueño; ALTER TABLE t OWNER TO grupo cambia la propiedad.
Pruebas
Unitarias: unidades de código. Integración: módulos en conjunto. End-to-end: simulan al usuario real. Aserciones verifican supuestos.
Python en Databricks
f-strings para interpolar, and/or, try/except, assert cond, 'mensaje'; spark.sql(f"...") y spark.table().
REST API de Jobs
Cada ejecución y cada tarea de una ejecución tiene un run_id único.
Restricciones
Delta admite NOT NULL y CHECK; los datos existentes deben cumplir la restricción.
Retry / timeout
Políticas de reintento y timeout por tarea para jobs inestables o colgados.
SCD
SCD Tipo 1 sobrescribe; Tipo 2 conserva historial con nuevas filas.
Secret scopes
Guardan credenciales; READ sobre el scope basta para usarlas; se muestran como REDACTED.
Serverless
Cómputo administrado por Databricks que inicia rápido.
Silver
Capa limpia, validada, deduplicada y enriquecida; optimizada para ETL.
Spark UI / Ganglia
Spark UI: stages, tareas, spill y GC. Ganglia (legado): CPU, memoria, red y carga del clúster.
SQL warehouse
Cómputo de Databricks SQL. Más tamaño = menos latencia; más clústeres (escalado) = más concurrencia; Auto Stop ahorra costo.
Structured Streaming
Procesa streams como tablas incrementales con checkpoints y write-ahead logs.
Tabla managed vs externa
Managed: Databricks gestiona datos y metadatos (DROP borra todo). Externa (con LOCATION): DROP solo borra metadatos.
Time travel
Consultar o restaurar versiones anteriores: SELECT ... VERSION AS OF n; RESTORE TABLE t TO VERSION AS OF n.
Transaction log
Log JSON de cada commit en _delta_log; guarda versiones y estadísticas de archivos.
Triggers
processingTime='N minutes': micro-batch periódico. once/availableNow: procesa lo disponible y se detiene.
UNION
UNION combina resultados sin duplicados; UNION ALL los conserva.
Unity Catalog
Gobernanza centralizada a nivel de cuenta: acceso, auditoría, linaje y descubrimiento; nombres catalog.schema.table.
VACUUM
Borra archivos sin uso más viejos que la retención (7 días por defecto); impide time travel a esas versiones.
Vistas dinámicas
Vistas con current_user()/is_member() para seguridad por filas y columnas.
Vistas temporales
Temp view: sesión. Global temp view: todo el clúster (global_temp), se pierde al reiniciarlo. View: persistente.
Watermark
withWatermark limita cuánto estado se guarda para datos tardíos; window() agrupa por intervalos.
