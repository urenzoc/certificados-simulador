1. Planificar y administrar una solución de Azure AI

25–30% del examen

Elegir servicios, desplegar, gobernar costos, monitorear, asegurar y aplicar IA responsable.

Estructura de Foundry

  • Recurso de Foundry: límite de gobernanza (despliegues de modelos, red, seguridad, conexiones). Proyecto: espacio aislado por equipo/app (agentes, evaluaciones, archivos). Varios equipos → un recurso y varios proyectos.
  • Se invoca siempre por el nombre del despliegue. Un despliegue fija modelo + versión + tipo + cuota.
  • El punto de conexión del proyecto da acceso a agentes, evaluaciones, Foundry Tools y a la API compatible con OpenAI (Responses).
  • Infraestructura repetible: plantillas Bicep; CI/CD de agentes hospedados con Azure Developer CLI (GitHub Actions o Azure DevOps).

Cuotas, límites y costos

  • La cuota se asigna en TPM (tokens por minuto) por despliegue; también hay límites de RPM. El límite estima tokens al llegar la petición (incluye max_tokens), no lo facturado.
  • Errores 429: reintentar con backoff respetando retry-after-ms, suavizar el tráfico, subir o redistribuir TPM.
  • Costos: Foundry monitoring + Azure Cost Management con etiquetas por despliegue.

Monitoreo y observabilidad

  • Azure Monitor (métricas y registros del despliegue, alertas); configuración de diagnóstico a Log Analytics/Storage para auditoría.
  • Tracing OpenTelemetry de Foundry exportado a Application Insights: llamadas al modelo, herramientas, latencia, tokens, excepciones.
  • Panel de monitoreo de agentes + evaluación continua sobre una muestra del tráfico real.
  • Salud del índice: estado e historial del indexador de Azure AI Search.

Trampas frecuentes

  • Data Zone limita el procesamiento a una zona; Standard regional a una sola región.
  • Batch no consume la cuota online.
  • Un 429 con métricas bajas suele ser por ráfagas: suaviza tráfico y respeta retry-after.

2. Implementar soluciones generativas y agénticas

30–35% del examen

Apps con modelos, RAG, agentes, multiagente, evaluación y optimización.

Consumir modelos

  • AIProjectClient(endpoint, DefaultAzureCredential()) → get_openai_client() → responses.create(model=<despliegue>, input=…).
  • Contexto entre turnos sin reenviar todo: pasar previous_response_id (Responses API) o usar una conversación.
  • Salidas estructuradas (JSON Schema estricto) vs. modo JSON (solo JSON válido).
  • Function calling: el modelo propone la función y argumentos → tu código la ejecuta → envías el resultado → el modelo responde. Valida los argumentos.

RAG

  • Pasos: dividir documentos en chunks (con superposición) → generar embeddings → indexar → recuperar los fragmentos relevantes → incluirlos como contexto.
  • Búsqueda híbrida (palabra clave + vector, fusionadas con RRF) + ranker semántico = mejor relevancia cuando hay códigos exactos y paráfrasis.
  • Recuperación agéntica de Azure AI Search / Foundry IQ: planifica varias subconsultas, usa el historial y devuelve citas; base de conocimiento reutilizable por varios agentes y que respeta permisos.
  • Fuentes indexadas (se ingieren) vs. remotas (se consultan en el momento sin ingerir).

  • Tipos de agente: prompt agent (definido por instrucciones, modelo y herramientas; versionado) y hosted agent (tu contenedor y framework; Foundry gestiona la infraestructura).
  • Publicar como Agent Application: URL estable e identidad propia; la implementación puede apuntar a versiones nuevas.
  • Entradas estructuradas para parametrizar recursos por inquilino en tiempo de ejecución.

  • Evaluación en la nube desde CI/CD para puntuar datasets grandes y fallar el build si hay regresión.
  • Benchmarks para comparar despliegues con datasets y lógica estándar.
  • Agent Optimizer: genera candidatos de instrucciones, descripciones de herramientas y selección de modelo, y los compara con evaluadores.

Ajustar la generación

  • Más determinismo: bajar temperatura (y no tocar top_p a la vez).
  • Menos latencia: limitar max tokens y usar streaming (mejora la percibida).
  • Few-shot como pares user/assistant previos; mensaje del sistema con rol, contrato de salida y comportamiento ante falta de evidencia.

Trampas frecuentes

  • File Search requiere vector store; Azure AI Search requiere índice.
  • Handoff transfiere el control; concurrente no.
  • Groundedness compara con el contexto; no necesita respuesta de referencia.

3. Implementar soluciones de visión por computadora

10–15% del examen

Generación y edición de imágenes y video, comprensión multimodal y seguridad visual.

Video con Sora 2

  • Trabajo asíncrono: crear → consultar estado por ID (queued, in_progress, completed, failed) → descargar MP4.
  • Imagen de referencia (input_reference) JPEG/PNG/WebP con dimensiones iguales al video; ancla el primer fotograma. El prompt sigue siendo obligatorio.
  • Remix con remix_video_id y un cambio por vez.
  • Restricciones: rechaza imágenes de entrada con rostros humanos, personas reales, personajes y música con copyright.

Comprensión multimodal

  • Texto e imagen en el mismo mensaje (image_url con URL pública o data URL base64; base64 si la URL es privada).
  • detail: low (rápido, barato), high (detalles finos), auto (por defecto).
  • Hasta 10 imágenes por solicitud de chat; GIF animado: solo se analiza el primer fotograma.
  • Texto alternativo breve + descripción extendida aparte para imágenes complejas.
  • Azure Vision: Read (OCR), Objects (cuadros), DenseCaptions (regiones), SmartCrops, captions neutrales en género.

Content Understanding para imágenes y video

  • Analizador con esquema de campos para resultados predecibles; salida JSON + Markdown.
  • Modo Standard (un archivo) vs. Pro (razonamiento entre varios documentos y datos de referencia).
  • Video: enableSegment + contentCategories para segmentar; returnDetails para frases con hablante y cambios de toma.

IA responsable visual

  • Content Safety Analyze Image: severidades 0, 2, 4, 6 en odio, sexual, violencia y autolesión.
  • Texto dentro de imágenes (OCR) = contenido no confiable: filtrarlo contra inyección indirecta antes de usar herramientas.
  • Marcas de agua y reglas de marca: paso determinista posterior a la generación y registro de procedencia.

Trampas frecuentes

  • La máscara indica dónde editar; transparencia del fondo es otra cosa.
  • low no activa la ruta de alta resolución.
  • Pro mode no aplica a entradas de imagen.

Conjunto de skills de IA que enriquece los documentos durante la indexación.
Sora
Generación de video asíncrona por jobs; remix aplica un cambio puntual a un video terminado.
Speech to text
Tiempo real para audio en vivo con baja latencia; por lotes para grabaciones.
Spotlighting
Marca el contenido de terceros como de menor confianza para que no se trate como instrucciones.
SSML
Marcado que controla pronunciación, pausas, velocidad, tono y énfasis de la voz sintetizada.
Streaming
Devuelve tokens a medida que se generan: mejora la latencia percibida, no la total.
temperature
0–2. Alto = respuestas más creativas y variadas; bajo = más deterministas.
Text Analytics for health
Extrae y vincula entidades clínicas de notas médicas.
Text to speech
SpeechConfig configura recurso y voz; AudioOutputConfig define el archivo; SpeechSynthesizer genera el audio.
Tipos de despliegue
Standard (región), Global Standard (global), Data Zone Standard (zona de datos), Provisioned (throughput reservado).
tool_choice
auto: el modelo decide; required: debe llamar una herramienta; none: ninguna.
top_p
Muestreo por núcleo: limita los tokens a la masa de probabilidad indicada.
Tracing de agentes
Registra cada paso del agente (entradas, salidas, tools, latencia, tokens) con OpenTelemetry en Application Insights.
Translator
Traduce texto y documentos; mejor con un solo idioma de origen por solicitud.
Transliteración
Convierte de un sistema de escritura a otro sin traducir el significado.
Uso de tokens
Principal indicador de costo: tokens de entrada y salida por interacción.
Vectorizer
Convierte texto en vectores con el mismo modelo usado en la indexación.
Versión de agente
Snapshot inmutable de modelo, instrucciones y herramientas que un despliegue referencia.
Voice Live
API de voz bidireccional de baja latencia con manejo de interrupciones.
Watermark / provenance
Paso posterior que aplica marca de agua y registra la procedencia antes de publicar.
Web Search / Bing
Información pública actual de internet durante la respuesta.
Workflow
Orquestación declarativa YAML con pasos, estado compartido (Local.*) y condiciones.
XPIA
Evaluador de ataques indirectos ocultos en el contenido recuperado.
