1. Arquitectura y componentes de Spark

20% del examen

Cómo se ejecuta un programa de Spark.

ComponenteRol
DriverEjecuta tu programa, crea la SparkSession, planifica el trabajo y coordina
Cluster managerAsigna recursos (standalone, YARN, Kubernetes)
Worker / executorProcesos JVM en los nodos que ejecutan tareas y guardan datos en caché
Core / slotCada núcleo ejecuta una tarea a la vez
  • Jerarquía de ejecución: Aplicación → Job (uno por acción) → Stage (se corta en cada shuffle) → Task (una por partición).
  • Transformaciones (lazy): select, filter, withColumn, join, groupBy… construyen un plan. Acciones: count, collect, show, take, write, first… disparan la ejecución.
  • Transformaciones estrechas (narrow: filter, select, map) no mueven datos; anchas (wide: groupBy, join, distinct, orderBy, repartition) provocan shuffle.
  • Catalyst optimiza el plan lógico; Tungsten optimiza memoria y generación de código.
  • DataFrame = colección distribuida con esquema (filas y columnas). Dataset = tipado (Scala/Java); en Python se usan DataFrames.
  • SparkSession: punto de entrada único (spark); spark.stop() la cierra.

Caché y niveles de almacenamiento

NivelComportamiento
MEMORY_ONLYEn memoria; lo que no cabe se recalcula
MEMORY_AND_DISKLo que no cabe se escribe a disco (predeterminado de cache() en DataFrames)
DISK_ONLYSolo disco
*_SER / _2Serializado / replicado en 2 nodos
  • cache() = persist() con el nivel por defecto; es lazy (se materializa con la primera acción). unpersist() libera.
  • Módulos: Spark Core, Spark SQL/DataFrames, Pandas API on Spark, Structured Streaming, MLlib.

Trampas frecuentes

  • count() es acción; groupBy() no.
  • Un stage termina donde hay shuffle.
  • cache() no ejecuta nada por sí solo.

2. Spark SQL

20% del examen

Leer, escribir y consultar con SQL.

df = spark.read.format("csv").option("header", True).option("inferSchema", True).load("/ruta")
df.write.mode("overwrite").partitionBy("pais").format("delta").save("/salida")
df.createOrReplaceTempView("ventas")
spark.sql("SELECT pais, SUM(monto) FROM ventas GROUP BY pais")
spark.sql("SELECT * FROM parquet.`/datos/archivo.parquet`")
Modo de guardadoSi el destino existe
error / errorifexists (por defecto)Falla
appendAgrega filas
overwriteReemplaza
ignoreNo hace nada
  • JDBC: spark.read.format("jdbc").option("url", …).option("dbtable", …); paralelismo con partitionColumn, lowerBound, upperBound, numPartitions.
  • Tablas persistentes: df.write.saveAsTable("t"); con bucketBy/sortBy (solo con saveAsTable) y partitionBy.
  • Vista temporal (createOrReplaceTempView) vive en la sesión; global temp view vive en la aplicación (global_temp.nombre).
  • Consultar archivos directamente: `SELECT * FROM json./ruta ` (también csv, orc, text, delta).

Trampas frecuentes

  • El modo por defecto es error, no overwrite.
  • bucketBy no funciona con save(), solo con saveAsTable().

3. API de DataFrame/Dataset

30% del examen

La sección con más peso: manipular columnas, filas, joins, fechas, UDF.

Columnas y filas

from pyspark.sql import functions as F
df.select("a", F.col("b").alias("bb"))
df.withColumn("total", F.col("p") * F.col("q"))
df.withColumnRenamed("old", "new").drop("tmp")
df.filter((F.col("edad") > 18) & F.col("pais").isin("PE", "CL"))
df.withColumn("item", F.explode("items"))        # una fila por elemento
df.withColumn("partes", F.split("nombre", " "))
df.dropDuplicates(["id"]).na.drop(subset=["email"]).na.fill({"edad": 0})

Agregaciones

  • groupBy(...).agg(F.count("*"), F.avg("x"), F.sum("y"), F.max("z")).
  • F.approx_count_distinct("col", rsd=0.05): conteo distinto aproximado (más barato que countDistinct).
  • df.describe() (count, mean, stddev, min, max) y df.summary() (añade percentiles).
  • Funciones de ventana: Window.partitionBy("a").orderBy("b") con row_number, rank, dense_rank, lag, lead.

Fechas

  • F.from_unixtime(epoch, "yyyy-MM-dd") convierte segundos Unix a texto; F.to_date, F.to_timestamp, F.date_format.
  • Extraer partes: F.year, F.month, F.dayofmonth, F.dayofweek, F.hour.
  • F.datediff, F.date_add, F.months_between, F.current_date().

Combinar DataFrames

OperaciónComportamiento
join(how="inner")Solo coincidencias (por defecto)
left / right / outer (full)Conserva no coincidentes del lado indicado
left_semiFilas de la izquierda que tienen coincidencia (sin columnas de la derecha)
left_antiFilas de la izquierda sin coincidencia
crossJoinProducto cartesiano
broadcast(df_pequeño)Envía la tabla chica a todos los executors y evita shuffle
union / unionAllPor posición (no elimina duplicados; usar distinct())
unionByNamePor nombre de columna (allowMissingColumns=True)

Esquemas, ordenar y convertir

  • Esquema explícito con StructType([StructField("id", IntegerType(), True), …]) o cadena DDL "id INT, nombre STRING".
  • printSchema(), orderBy/sort con F.desc(), collect() (lista de Row al driver: cuidado con OOM), take(n), toPandas(), spark.createDataFrame(lista, esquema).

UDF y variables compartidas

  • UDF de Python: F.udf(func, StringType()) o decorador @F.udf; para SQL spark.udf.register. Son más lentas que funciones integradas (serialización fila a fila).
  • Pandas UDF (@pandas_udf) vectorizadas con Arrow: mucho más rápidas.
  • Variable broadcast: copia de solo lectura en cada executor (tablas de búsqueda).
  • Accumulator: contador que los executors solo pueden sumar y el driver lee.

Trampas frecuentes

  • union no alinea por nombre.
  • Prefiere funciones de pyspark.sql.functions antes que UDF.
  • collect() trae todo al driver.

4. Diagnóstico y ajuste

10% del examen

Particiones, skew, AQE y logs.

HerramientaUso
repartition(n | col)Sube o baja particiones con shuffle completo; reparte uniforme
coalesce(n)Solo reduce particiones sin shuffle completo; ideal antes de escribir
spark.sql.shuffle.partitionsParticiones tras un shuffle (por defecto 200)
broadcast joinEvitar shuffle con tablas pequeñas (spark.sql.autoBroadcastJoinThreshold, 10 MB por defecto)
  • Skew (datos sesgados): pocas tareas tardan mucho más. Soluciones: AQE skew join, salting, filtrar claves nulas.
  • AQE (Adaptive Query Execution, activado por defecto en Spark 3.2+): en tiempo de ejecución combina particiones pequeñas tras el shuffle, cambia sort-merge join a broadcast join y divide particiones sesgadas.
  • OOM del driver: collect()/toPandas() grandes o broadcast enorme. OOM de executor: particiones demasiado grandes, skew. Clúster infrautilizado: pocas particiones respecto a los cores.
  • Spark UI: jobs, stages, tareas, spill a disco, tamaño de shuffle; logs de driver y executors.

Trampas frecuentes

  • coalesce no puede aumentar particiones.
  • AQE no necesita que cambies el código.

5. Structured Streaming

10% del examen

Streaming como tabla que crece sin límite.

q = (spark.readStream.format("kafka").option("subscribe", "eventos").load()
     .withWatermark("ts", "10 minutes")
     .groupBy(F.window("ts", "5 minutes"), "tipo").count()
     .writeStream.outputMode("update")
     .option("checkpointLocation", "/chk/eventos")
     .trigger(processingTime="1 minute")
     .toTable("conteos"))
  • Modelo de micro-lotes; exactamente una vez con fuentes reproducibles + checkpoint + sinks idempotentes.
  • Modos de salida: append (solo filas nuevas finales), complete (toda la tabla de resultados; agregaciones), update (solo filas cambiadas).
  • Triggers: por defecto (lo antes posible), processingTime, availableNow=True (procesa lo pendiente y para).
  • Sinks: archivos/Delta, Kafka, foreachBatch, console y memory (pruebas).
  • Ventanas: de saltos fijos (tumbling), deslizantes (sliding) y de sesión.
  • Deduplicar: dropDuplicates(["id"]) sin watermark guarda estado indefinido; con withWatermark el estado se limpia. dropDuplicatesWithinWatermark (Spark 3.5).

Trampas frecuentes

  • append con agregación requiere watermark.
  • Sin checkpoint no hay tolerancia a fallos.

6. Spark Connect

5% del examen

Cliente ligero desacoplado del driver.

  • Arquitectura cliente-servidor: el cliente envía planes lógicos (gRPC) al servidor Spark, que los ejecuta. Permite clientes ligeros, actualizaciones independientes y aislamiento (un cliente que falla no tumba el driver).
  • Se conecta con SparkSession.builder.remote("sc://host:15002").getOrCreate().
  • Modos de despliegue: client (el driver corre donde se lanza la app), cluster (el driver corre dentro del clúster) y local (todo en una máquina, para desarrollo).
  • No soporta APIs de RDD/SparkContext directo.

7. Pandas API on Spark

5% del examen

Sintaxis de pandas a escala distribuida.

  • import pyspark.pandas as ps; ps.read_csv, psdf = df.pandas_api(), psdf.to_spark().
  • Ventaja: reutilizar código pandas sobre datos que no caben en una máquina.
  • Pandas UDF: @pandas_udf("double") def f(s: pd.Series) -> pd.Series (Series a Series), también iteradores y agregaciones (Series a escalar); applyInPandas por grupo, mapInPandas.
Glosario rápido (44 términos)
approx_count_distinct
Conteo aproximado de distintos; rsd mayor = más rápido. countDistinct es exacto.
AQE / skew
Adaptive Query Execution ajusta el plan en ejecución; spark.sql.adaptive.skewJoin.enabled divide particiones con skew.
Broadcast join
Envía el DataFrame pequeño a todos los ejecutores para evitar el shuffle del grande; umbral spark.sql.autoBroadcastJoinThreshold.
cache / persist
cache() = persist() con MEMORY_AND_DISK; persist(nivel) permite MEMORY_ONLY, DISK_ONLY, _SER y réplicas _2.
count
count() es una acción que devuelve el número de filas.
crossJoin
Producto cartesiano de dos DataFrames.
DataFrame / RDD
El DataFrame es una tabla distribuida e inmutable construida sobre RDDs.
DataFrameWriter
df.write.mode(...).partitionBy(...).parquet(path); partitionBy organiza carpetas por valor.
describe / summary
describe(cols): count, mean, stddev, min, max. summary(): además percentiles.
distinct / dropDuplicates
Eliminan filas duplicadas; dropDuplicates admite subset de columnas.
Driver
Proceso que corre main, crea el plan y programa las tareas; no es tolerante a fallos ni escala horizontalmente.
Ejecutor
Proceso en un worker que ejecuta tareas y guarda datos cacheados.
Evaluación perezosa
Las transformaciones solo construyen el plan; se ejecuta al llamar una acción.
Fechas UNIX
from_unixtime(col, formato) convierte segundos epoch a string; cast('timestamp') a timestamp; month() extrae el mes.
filter / where
Condiciones con & y |, cada una entre paréntesis, sobre col('x').
groupBy / agg
groupBy devuelve GroupedData; agg(sum(col('x')).alias('y')) agrega.
Job
Se crea uno por cada acción; se divide en stages.
join
df1.join(df2, on, how); how por defecto 'inner'; on como string, lista de strings o expresión.
lit / col / cast
lit() crea constantes; col() referencia columnas; .cast() cambia el tipo.
lower / upper
lower(col('x')) y upper(col('x')) convierten mayúsculas/minúsculas.
Modos de despliegue
Cluster: driver en un worker. Client: driver en la máquina cliente. Local: todo en una máquina.
Narrow vs wide
Narrow: sin shuffle (select, filter, union). Wide: con shuffle (join, groupBy, distinct, sort, repartition).
Nodo worker
Máquina del clúster que aloja ejecutores.
Nulos
na.drop('all'|'any') / dropna eliminan; na.fill(valor, subset) / fillna reemplazan.
orderBy / sort
Ordenan filas; asc()/desc() o ascending=False.
Out-of-memory
El driver o un ejecutor no tiene memoria para los datos que recolecta o procesa.
printSchema
printSchema() imprime el esquema; df.schema lo devuelve como StructType.
regexp_replace
regexp_replace(col, patrón, reemplazo) reemplaza texto con regex; regexp_extract extrae.
repartition vs coalesce
repartition(n): shuffle completo, sube o baja particiones. coalesce(n): solo reduce, sin shuffle completo, puede causar skew.
sample
sample(withReplacement=False, fraction, seed); True = con reemplazo.
select / drop
select('a','b') elige columnas; drop('a','b') las quita (nombres como string).
Shuffle
Redistribución de datos entre particiones (red/disco); marca límites de stage.
Slot
Core disponible para ejecutar una tarea en paralelo.
spark.read
spark.read.format(...).schema(...).load(path) o spark.read.parquet(path); read es propiedad, sin paréntesis.
spark.sql / vistas
df.createOrReplaceTempView('t') y spark.sql('SELECT ... FROM t') devuelve un DataFrame.
spark.sql.shuffle.partitions
Número de particiones tras un shuffle (200 por defecto).
split / explode
split(col, patrón) devuelve un array; explode crea una fila por elemento. Son funciones, no métodos de Column.
Stage
Grupo de tareas que pueden ejecutarse en paralelo; los shuffles separan stages.
take / collect / show
take(n)/head(n): primeras n filas. collect(): todas al driver. show(): imprime 20 filas.
Task
Unidad más granular: una partición procesada por un conjunto de transformaciones en un ejecutor.
Transformación vs acción
Transformaciones (select, filter, join) son perezosas; acciones (count, collect, take, show) disparan la ejecución.
UDF
udf(func, tipo) en Python (StringType por defecto); spark.udf.register('NOMBRE', func) para SQL.
union / unionByName
union() une por posición; unionByName() une por nombre de columna.
withColumn / withColumnRenamed
withColumn('c', expr) agrega o reemplaza; withColumnRenamed('vieja','nueva') renombra.
