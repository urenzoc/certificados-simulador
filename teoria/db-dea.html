1. Databricks Intelligence Platform

Arquitectura, Delta Lake, Unity Catalog y cómputo.

  • Plano de control (servicios de Databricks: UI, notebooks, jobs) vs. plano de cómputo/datos (clústeres en tu nube o serverless; los datos quedan en tu almacenamiento).
  • Lakehouse: almacenamiento de data lake + gestión transaccional y gobernanza de un warehouse.
  • Arquitectura medallion: bronze (bruto), silver (limpio y conformado), gold (agregado para negocio).

Delta Lake

  • Parquet + registro de transacciones (_delta_log) → transacciones ACID, esquema aplicado, versiones.
  • Time travel: SELECT * FROM t VERSION AS OF 3 / TIMESTAMP AS OF; RESTORE TABLE t TO VERSION AS OF 3; DESCRIBE HISTORY t.
  • OPTIMIZE compacta archivos pequeños; ZORDER BY (o mejor Liquid Clustering) organiza para saltar datos; VACUUM borra archivos no referenciados más antiguos que la retención (7 días por defecto) y limita el time travel.
  • MERGE INTO para upserts; CREATE TABLE … CLONE (deep copia datos, shallow solo metadatos).

Unity Catalog

  • Jerarquía: metastore → catálogo → esquema → tabla/vista/volumen/función/modelo. Nombre de tres niveles catalogo.esquema.tabla.
  • Gobierna permisos, linaje, auditoría y descubrimiento en todos los workspaces.
  • Volúmenes: archivos no tabulares gobernados (/Volumes/cat/esq/vol/).

Cómputo

TipoUso
All-purpose (interactivo)Desarrollo en notebooks; compartido; más caro por DBU
Jobs computeSe crea y termina con cada ejecución; más barato para producción
Serverless (notebooks, jobs, pipelines)Arranque inmediato, sin administrar; pagas por uso
SQL warehouse (pro/serverless)Consultas SQL y BI

Trampas frecuentes

  • VACUUM rompe el time travel a versiones anteriores a la retención.
  • Jobs compute es más barato que all-purpose para tareas programadas.

2. Ingesta y carga de datos

COPY INTO, Auto Loader, Lakeflow Connect y otros métodos.

MétodoCuándo

Auto Loader (cloudFiles)Millones de archivos, llegada continua, inferencia y evolución de esquema; batch con availableNow
Lakeflow ConnectConectores administrados a fuentes empresariales (Salesforce, SQL Server, Workday…)
JDBC/ODBC/REST en notebookFuentes sin conector, orquestado con Lakeflow Jobs
Partner Connect / sociosHerramientas de terceros (Fivetran, etc.)
COPY INTO main.bronze.ventas
FROM '/Volumes/main/raw/ventas/'
FILEFORMAT = CSV
FORMAT_OPTIONS ('header' = 'true')
COPY_OPTIONS ('mergeSchema' = 'true');

spark.readStream.format("cloudFiles")
  .option("cloudFiles.format", "json")
  .option("cloudFiles.schemaLocation", "/chk/schema")
  .load("/Volumes/main/raw/eventos")
  • Auto Loader: modos de evolución addNewColumns (por defecto), rescue (columnas nuevas van a _rescued_data), failOnNewColumns, none.
  • Semiestructurado: from_json, notación col:campo sobre JSON en texto, tipo VARIANT (parse_json).
  • Archivos no estructurados: formato binaryFile a tablas Delta o volúmenes.

Trampas frecuentes

  • COPY INTO y Auto Loader no recargan archivos ya procesados.
  • La ubicación de esquema es obligatoria para inferir esquema en Auto Loader.

3. Transformación y modelado

Limpiar bronze a silver, joins, agregaciones y objetos gold.

  • Limpieza: castear tipos, manejar nulos (coalesce, na.fill), deduplicar (dropDuplicates, ROW_NUMBER() OVER).
  • Joins inner, left, broadcast, multicolumna y cross; UNION (quita duplicados) vs. UNION ALL.
  • explode para arreglos; funciones de orden superior transform, filter, exists sobre arreglos.
  • count_if, approx_count_distinct, PIVOT.
Objeto goldClave
VistaConsulta guardada; se calcula al leer
Vista temporalSolo en la sesión
Materialized viewResultado precalculado y refrescado de forma incremental (Lakeflow Declarative Pipelines / DBSQL)
Streaming tableProcesa datos nuevos de forma incremental (solo anexado)
Tabla DeltaDatos persistentes administrados
  • Calidad con expectations en Lakeflow Declarative Pipelines: EXPECT (registra), ON VIOLATION DROP ROW (descarta), ON VIOLATION FAIL UPDATE (falla). Restricciones CHECK y NOT NULL en tablas Delta.

SQL de escritura que más se pregunta

SentenciaEfecto
CREATE OR REPLACE TABLE … AS SELECT (CTAS)Crea/reemplaza la tabla con el resultado; el esquema se infiere; conserva historial si ya existía
INSERT OVERWRITEReemplaza los datos; falla si el esquema no coincide (no cambia el esquema)
INSERT INTOAgrega filas (puede duplicar si se reejecuta)
MERGE INTOUpsert: WHEN MATCHED UPDATE/DELETE, WHEN NOT MATCHED INSERT; evita duplicados
CREATE TABLE … USING CSV LOCATIONTabla externa sobre archivos (no es Delta: sin ACID ni time travel)
MERGE INTO silver.clientes t
USING updates s ON t.id = s.id
WHEN MATCHED AND s.op = "D" THEN DELETE
WHEN MATCHED THEN UPDATE SET *
WHEN NOT MATCHED THEN INSERT *;

Lakeflow Declarative Pipelines (antes Delta Live Tables)

  • CREATE OR REFRESH STREAMING TABLE para ingesta incremental (con STREAM(...) o read_files) y CREATE OR REFRESH MATERIALIZED VIEW para agregados.
  • Modo triggered (procesa y se detiene) vs. continuous (siempre activo); entorno development (reutiliza clúster, sin reintentos) vs. production.
  • El event log guarda calidad de datos, linaje y métricas.

Trampas frecuentes

  • UNION elimina duplicados; UNION ALL no.
  • Materialized view ≠ vista: la primera guarda resultados.
  • INSERT OVERWRITE no puede cambiar el esquema; CREATE OR REPLACE sí.

4. Lakeflow Jobs

Orquestación de tareas.

  • Un job es un DAG de tareas: notebook, SQL, dashboard, pipeline, Python wheel, JAR, dbt, tarea de job.
  • Dependencias "depende de"; tareas condicionales (If/else) y For each para iterar.
  • Reintentos por tarea, tiempo de espera, notificaciones por correo/webhook.
  • Parámetros de job y de tarea; dbutils.jobs.taskValues para pasar valores entre tareas.
  • Repair run: volver a ejecutar solo las tareas fallidas.
DisparadorCuándo
Programado (cron)A una hora fija
Llegada de archivosAl aparecer archivos nuevos en una ubicación
Actualización de tablaCuando cambian tablas de origen
ContinuoSiempre en ejecución

5. CI/CD

Git y Databricks Asset Bundles.

  • Git folders (Repos): clonar, ramas, commit, push, pull y pull request desde el workspace.
  • Bundles (databricks.yml): empaquetan jobs, pipelines y otros recursos como código. Targets (dev, test, prod) con variables y overrides.
  • CLI: databricks bundle validate, databricks bundle deploy -t prod, databricks bundle run <job>.

6. Diagnóstico, monitoreo y optimización

Historial de ejecuciones, Spark UI y layout de datos.

  • Comparar duraciones en el historial de ejecuciones contra una línea base; vista DAG y tasas de fallo.
  • Spark UI: skew (una tarea mucho más lenta), shuffle grande, spill a disco.
  • Liquid Clustering (CLUSTER BY): reemplaza particiones y ZORDER, se puede cambiar sin reescribir; CLUSTER BY AUTO elige las claves.
  • Predictive optimization: Databricks ejecuta OPTIMIZE y VACUUM automáticamente en tablas administradas de UC.
  • Fallos de arranque de clúster, conflictos de librerías, OOM del driver/executor.

7. Gobernanza y seguridad

Tablas administradas/externas, permisos y seguridad a nivel de fila/columna.

AdministradaExterna
UbicaciónAlmacenamiento administrado por UCRuta que tú indicas (LOCATION)
DROP TABLEBorra metadatos y datosBorra solo metadatos
Optimización automáticaSí (predictive optimization)No
GRANT USE CATALOG ON CATALOG main TO `analistas`;
GRANT USE SCHEMA ON SCHEMA main.ventas TO `analistas`;
GRANT SELECT ON TABLE main.ventas.pedidos TO `analistas`;
REVOKE SELECT ON TABLE main.ventas.pedidos FROM `analistas`;
  • Para leer una tabla se necesita USE CATALOG + USE SCHEMA + SELECT. Los privilegios se heredan hacia abajo.
  • El propietario de un objeto tiene todos los permisos sobre él.
  • Filtros de fila y máscaras de columna con funciones (p. ej. is_account_group_member("rrhh")).
  • ABAC: políticas basadas en etiquetas gobernadas que aplican filtros y máscaras a escala.
  • Principales: usuarios, grupos y service principals (para automatización).

Trampas frecuentes

  • Sin USE CATALOG/USE SCHEMA, SELECT sobre la tabla no basta.
  • DROP de una tabla externa no borra los archivos.
Glosario rápido (64 términos)
Alertas
Alertas sobre el valor de una consulta; destinos correo, Slack, Teams y webhook; plantillas personalizadas.
APPLY CHANGES INTO
Aplica feeds CDC en DLT, ordenando con SEQUENCE BY.
Auto Loader
Ingesta incremental de archivos nuevos con Structured Streaming; schemaLocation, evolución de esquema y file notification.
Auto Optimize
Optimized Writes + Auto Compaction: compactan durante las escrituras hacia ~128 MB, sin Z-Order.
Bronze
Capa de datos sin procesar con el historial completo.
Change Data Feed
Registra cambios fila a fila (_change_type); útil cuando cambia una fracción pequeña de registros.
Checkpoint
Guarda el progreso y estado del stream; da tolerancia a fallos y no se comparte entre streams.
CLONE
DEEP CLONE copia datos y metadatos; SHALLOW CLONE solo referencia los archivos de la fuente.
Cluster pools
Instancias inactivas listas que reducen el tiempo de inicio del clúster.
Clúster all-purpose
Clúster interactivo para desarrollo y análisis; más caro que un job cluster.
Columna generada
GENERATED ALWAYS AS (expr): Delta calcula el valor automáticamente.
Comandos mágicos
%python/%sql/%scala/%r cambian el lenguaje de la celda; %sh corre solo en el driver; %pip instala librerías del notebook; %run incluye otro notebook.
Control plane / data plane
Control plane: app web, notebooks, jobs y consultas en la cuenta de Databricks. Data plane: VM del clúster y datos en la cuenta cloud del cliente.
COPY INTO
Carga idempotente de archivos con SQL: omite los que ya se cargaron.
Cron
Expresión para programaciones complejas de jobs.
CTAS / INSERT OVERWRITE
CTAS reemplaza datos y esquema; INSERT OVERWRITE reemplaza solo datos. Ambos conservan el historial.
Dashboards SQL
Varias visualizaciones por consulta, parámetros de filtro, refresco programado y Query History/profile.
Data Explorer
Interfaz para explorar datos y gestionar permisos sobre tablas.
Data skipping
Delta usa min/max por archivo (primeras 32 columnas, en el log) para saltar archivos.
Databricks Repos
Carpetas Git: clone, pull, commit/push, ramas y diffs. Pull requests, aprobación y borrar ramas se hacen en el proveedor Git.
DBFS
Databricks File System: abstracción sobre el almacenamiento de objetos con rutas tipo Unix.
dbutils
Utilidades: widgets (parámetros), notebook.run, secrets.get (se muestra REDACTED), fs.
Delta Lake
Formato abierto: Parquet + log JSON (_delta_log) con ACID, time travel y evolución de esquema.
Delta Live Tables
Pipelines declarativos con tablas LIVE/STREAMING, expectativas y modos Triggered/Continuous.
Delta Sharing
Protocolo abierto para compartir datos con otras organizaciones y plataformas.
DESCRIBE HISTORY / DETAIL / EXTENDED
HISTORY: versiones y quién cambió. DETAIL: ubicación y archivos. EXTENDED: tipo de tabla, propiedades, restricciones y comentarios.
Expectativas DLT
Sin ON VIOLATION: conserva y reporta. DROP ROW: descarta y reporta. FAIL UPDATE: detiene el pipeline.
from_json
Convierte un string JSON en struct; requiere el esquema.
Funciones de arrays
explode: una fila por elemento. flatten: aplana arrays anidados. collect_set: valores únicos. FILTER/TRANSFORM: funciones de orden superior con lambdas.
Gold
Capa de agregados de negocio optimizada para consultas, dashboards y ML.
GRANT / privilegios
GRANT priv ON TABLE t TO principal. MODIFY = agregar/borrar/modificar; USAGE es requisito para acceder a objetos del schema.
Job cluster
Clúster que se crea para un job y termina al finalizar; recomendado para producción.
Jobs / Workflows
Orquestan tareas con dependencias, clústeres por tarea, parámetros, reintentos y notificaciones.
Lakehouse
Une data lake y data warehouse: formatos abiertos, ACID, BI y ML, streaming y batch, esquema impuesto y evolutivo.
MERGE INTO
Inserta, actualiza o elimina según coincidencias; evita duplicados.
MLflow UDF
mlflow.pyfunc.spark_udf(spark, model_uri) registra un modelo como UDF de Spark.
Modos de salida
append (solo filas nuevas), complete (reescribe todo el resultado), update.
Modos DLT
Triggered: una vez. Continuous: siempre. Development: reutiliza el clúster. Production: reintenta y termina el clúster.
OPTIMIZE / ZORDER
OPTIMIZE compacta archivos pequeños; ZORDER BY agrupa valores de columnas de filtro para data skipping.
Particionamiento
Particionar por columnas de baja cardinalidad (p. ej. fecha); el sobreparticionado degrada el rendimiento.
Permisos de clúster
Can Attach To: ver métricas/Spark UI. Can Restart: iniciar/terminar. Can Manage: editar configuración.
Propiedad (owner)
El creador es dueño; ALTER TABLE t OWNER TO grupo cambia la propiedad.
Pruebas
Unitarias: unidades de código. Integración: módulos en conjunto. End-to-end: simulan al usuario real. Aserciones verifican supuestos.
Python en Databricks
f-strings para interpolar, and/or, try/except, assert cond, 'mensaje'; spark.sql(f"...") y spark.table().
REST API de Jobs
Cada ejecución y cada tarea de una ejecución tiene un run_id único.
Restricciones
Delta admite NOT NULL y CHECK; los datos existentes deben cumplir la restricción.
Retry / timeout
Políticas de reintento y timeout por tarea para jobs inestables o colgados.
SCD
SCD Tipo 1 sobrescribe; Tipo 2 conserva historial con nuevas filas.
Secret scopes
Guardan credenciales; READ sobre el scope basta para usarlas; se muestran como REDACTED.
Serverless
Cómputo administrado por Databricks que inicia rápido.
Silver
Capa limpia, validada, deduplicada y enriquecida; optimizada para ETL.
Spark UI / Ganglia
Spark UI: stages, tareas, spill y GC. Ganglia (legado): CPU, memoria, red y carga del clúster.
SQL warehouse
Cómputo de Databricks SQL. Más tamaño = menos latencia; más clústeres (escalado) = más concurrencia; Auto Stop ahorra costo.
Structured Streaming
Procesa streams como tablas incrementales con checkpoints y write-ahead logs.
Tabla managed vs externa
Managed: Databricks gestiona datos y metadatos (DROP borra todo). Externa (con LOCATION): DROP solo borra metadatos.
Time travel
Consultar o restaurar versiones anteriores: SELECT ... VERSION AS OF n; RESTORE TABLE t TO VERSION AS OF n.
Transaction log
Log JSON de cada commit en _delta_log; guarda versiones y estadísticas de archivos.
Triggers
processingTime='N minutes': micro-batch periódico. once/availableNow: procesa lo disponible y se detiene.
UNION
UNION combina resultados sin duplicados; UNION ALL los conserva.
Unity Catalog
Gobernanza centralizada a nivel de cuenta: acceso, auditoría, linaje y descubrimiento; nombres catalog.schema.table.
VACUUM
Borra archivos sin uso más viejos que la retención (7 días por defecto); impide time travel a esas versiones.
Vistas dinámicas
Vistas con current_user()/is_member() para seguridad por filas y columnas.
Vistas temporales
Temp view: sesión. Global temp view: todo el clúster (global_temp), se pierde al reiniciarlo. View: persistente.
Watermark
withWatermark limita cuánto estado se guarda para datos tardíos; window() agrupa por intervalos.
