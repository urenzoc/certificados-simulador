1. Conceptos básicos de datos

25–30% del examen

Tipos de datos, formatos, almacenes, cargas de trabajo y roles.

Formas de representar datos

SemiestructuradoEstructura flexible auto-descrita (claves, etiquetas); cada entidad puede tener campos distintosJSON, XML, YAML
No estructuradoSin estructura predefinidaImágenes, video, audio, PDF, texto libre

Almacenes de datos

  • Bases NoSQL: clave-valor, documento, familia de columnas y grafo.
  • Almacenes de archivos/objetos: data lake sobre Blob/ADLS Gen2.

Memoriza

  • ACID: Atomicidad (todo o nada), Consistencia (de un estado válido a otro), Aislamiento (transacciones concurrentes no interfieren), Durabilidad (lo confirmado persiste).
  • Data warehouse = relacional, esquema en escritura. Data lake = archivos, esquema en lectura. Lakehouse = data lake con capa transaccional (Delta Lake).

Roles

RolResponsabilidades
Administrador de bases de datos (DBA)Disponibilidad, rendimiento, copias de seguridad, seguridad y permisos de la base
Ingeniero de datosPipelines de ingesta y transformación, limpieza, almacenes de datos
Analista de datosModelar, explorar y visualizar datos; informes y dashboards (Power BI)

Trampas frecuentes

  • JSON es semiestructurado, no no-estructurado.
  • Parquet/ORC son columnares; Avro es por filas.
  • OLTP normaliza para evitar duplicados; OLAP desnormaliza para consultar rápido.

2. Datos relacionales en Azure

20–25% del examen

Modelo relacional, SQL y la familia Azure SQL.

Conceptos relacionales

  • Tablas (entidades) con filas y columnas tipadas.
  • Clave principal (PK): identifica cada fila de forma única. Clave externa (FK): referencia la PK de otra tabla.
  • Normalización: separar datos en tablas para eliminar redundancia y anomalías de actualización (1FN, 2FN, 3FN). Cuesta más JOIN al consultar.

ObjetoQué es

ÍndiceEstructura que acelera búsquedas a cambio de más almacenamiento y escrituras más lentas

Familia Azure SQL

Azure SQL DatabasePaaSApps nuevas en la nube; base única o grupo elástico; serverless e Hyperscale
Azure SQL EdgeIoTDispositivos perimetrales con streaming
  • Bases de datos de código abierto administradas: Azure Database for PostgreSQL, Azure Database for MySQL (y MariaDB, en retiro). Ofrecen alta disponibilidad, copias y escalado sin administrar el servidor.

Trampas frecuentes

  • Managed Instance = máxima compatibilidad PaaS; SQL Database = menos administración, menos compatibilidad de instancia.
  • TRUNCATE es DDL aunque borre datos.
  • Más normalización = menos redundancia, pero más JOIN.

3. Datos no relacionales en Azure

15–20% del examen

Azure Storage y Azure Cosmos DB.

Azure Storage

ServicioCaracterísticas
Blob StorageObjetos no estructurados. Blobs en bloques (archivos), en anexos (logs), en páginas (discos de VM). Niveles Hot, Cool, Cold, Archive
Data Lake Storage Gen2Blob + espacio de nombres jerárquico (carpetas reales) y ACL POSIX; base para analítica
Azure FilesRecursos compartidos SMB y NFS en la nube; reemplaza servidores de archivos
Table StorageNoSQL clave-valor: PartitionKey + RowKey; esquema flexible; barato

Azure Cosmos DB

Base NoSQL multimodelo, distribuida globalmente, con latencia de milisegundos, escalado elástico (RU/s), SLA de 99.999 % en lectura/escritura multirregión y cinco niveles de consistencia (fuerte, obsolescencia limitada, sesión, prefijo coherente, eventual).

APIModeloÚsala cuando…
NoSQL (nativa)Documentos JSON, consulta tipo SQLProyecto nuevo sin dependencia previa
MongoDBDocumentos BSONMigras una app MongoDB
PostgreSQLRelacional distribuido (Citus)Necesitas PostgreSQL escalado horizontalmente
Apache CassandraFamilia de columnasMigras desde Cassandra
TableClave-valorMigras desde Table Storage y quieres distribución global
Apache GremlinGrafoRelaciones complejas: redes sociales, recomendaciones

Trampas frecuentes

  • Table Storage (barato, simple) ≠ Cosmos DB for Table (global, baja latencia, más caro).
  • El espacio de nombres jerárquico es lo que convierte Blob en Data Lake Gen2.
  • Cosmos DB es la respuesta cuando piden "distribución global" o "latencia de milisegundos en cualquier región".

4. Cargas de trabajo de analítica

25–30% del examen

Ingesta, almacenes analíticos, tiempo real y Power BI.

Analítica a gran escala

  • ETL: transformar antes de cargar. ELT: cargar en bruto y transformar en el destino (típico en data lake/lakehouse).
  • Ingesta con pipelines: Azure Data Factory o Fabric Data Factory (pipelines y flujos de datos).
  • Almacenes analíticos: data warehouse relacional (esquema estrella: tabla de hechos con medidas y tablas de dimensiones con atributos) y data lake/lakehouse (archivos Parquet/Delta).
ServicioPara qué
Microsoft FabricPlataforma SaaS unificada: OneLake, Data Factory, Data Engineering, Data Warehouse, Real-Time Intelligence, Power BI
Azure DatabricksPlataforma Apache Spark administrada; lakehouse con Delta Lake; ciencia e ingeniería de datos
Azure Synapse AnalyticsAnalítica integrada (pools SQL y Spark); hoy Microsoft orienta los proyectos nuevos a Fabric
Azure Data FactoryOrquestación de pipelines e integración de datos
OneLakeData lake único lógico de Fabric para toda la organización

Tiempo real

DatosAcumulados y procesados juntosProcesados al llegar, continuamente

  • Servicios: Azure Event Hubs (ingesta de eventos masiva), Azure Stream Analytics (consultas SQL sobre streams), Fabric Real-Time Intelligence (Eventstreams, Eventhouse con KQL), Spark Structured Streaming en Databricks/Fabric, Azure Data Explorer (KQL sobre telemetría).

Power BI

  • Componentes: Power BI Desktop (crear modelos e informes), servicio Power BI (publicar, compartir, dashboards), apps móviles.
  • Modelo de datos: tablas, relaciones, medidas (cálculos DAX agregados), columnas calculadas y jerarquías (año → trimestre → mes) para obtener detalles.
  • Informe = varias páginas interactivas; dashboard = una página de iconos anclados.

Trampas frecuentes

  • Hechos = números medibles; dimensiones = contexto descriptivo.
  • Event Hubs ingiere; Stream Analytics procesa.
  • Medida DAX se calcula al consultar; columna calculada se guarda por fila.
Glosario rápido (79 términos)
ACID
Atomicidad (todo o nada), Consistencia (estado válido), Aislamiento (concurrencia = ejecución secuencial) y Durabilidad (lo confirmado persiste).
Almacén de objetos
Archivos grandes con metadatos e ID único; Azure Blob Storage.
Analista de datos
Explora, limpia y modela datos y crea informes y visualizaciones.
Analítica cognitiva
Saca inferencias de datos no estructurados (audio, imágenes, texto), p. ej. transcribir audio.
Analítica descriptiva
Responde qué pasó, a partir de datos históricos.
Analítica diagnóstica
Responde por qué pasó algo.
Analítica predictiva
Responde qué es probable que pase en el futuro.
Analítica prescriptiva
Responde qué acciones tomar para lograr un objetivo.
Apache Spark
Framework open source de procesamiento paralelo en memoria para big data.
App de Power BI
Paquete de dashboards e informes para distribuir a la organización.
ARM template
Plantilla JSON para desplegar grupos de recursos interdependientes de forma repetible.
AzCopy
CLI para copiar datos hacia/desde Azure Storage, con SAS o Entra ID.
Azure Blob Storage
Objetos no estructurados en contenedores; niveles Hot, Cool, Cold y Archive.
Azure Cosmos DB
NoSQL globalmente distribuida y multimodelo (NoSQL, MongoDB, Cassandra, Gremlin, Table).
Azure Data Factory
Orquesta ingesta: pipelines, actividades, linked services, integration runtime (cómputo) y triggers (inician el pipeline).
Azure Data Studio / SSMS / SSDT
Data Studio: multiplataforma. SSMS: solo Windows. SSDT: desarrollo offline orientado a proyectos. sqlcmd: CLI.
Azure Databricks
Plataforma de analítica colaborativa basada en Apache Spark.
Azure Files
Recursos compartidos SMB/NFS que se montan como unidad de red.
Azure SQL Database
PaaS administrado: parches, backups y alta disponibilidad automáticos; ideal para apps nuevas/SaaS.
Azure Synapse Analytics
Data warehousing (SQL pools) + big data (Spark) en un servicio; Synapse Studio es la interfaz.
Azure Table Storage
Clave-valor NoSQL; la clave es partition key + row key; sin integridad referencial.
Base de documentos
Guarda documentos JSON con esquema flexible; cada documento contiene toda la entidad.
Block / page / append blob
Block: archivos discretos. Page: acceso aleatorio (discos de VM). Append: logs.
Clave primaria / foránea
La clave primaria identifica cada fila; la foránea referencia la clave primaria de otra tabla y define la relación.
Clave-valor
Almacén con búsqueda rápida por clave; el valor es opaco. Ideal para caché, sesiones y preferencias.
Cuenta de almacenamiento
Contenedor de nivel superior para Blob, Files, Table y Queue; se crea con az storage account create.
Dashboard
Una página de tiles anclados de uno o más informes; se crea en el servicio Power BI.
Data lake
Repositorio de datos sin procesar en cualquier formato.
Data Lake Storage
Blob con espacio de nombres jerárquico y ACL; compatible con HDFS y optimizado para analítica.
Data warehouse
Almacén de datos estructurados y limpios para consultas analíticas y reportes.
Datos estructurados / semi / no estructurados
Estructurados: esquema fijo (tablas). Semiestructurados: campos propios por registro (JSON). No estructurados: sin esquema (audio, video, imágenes).
DBA
Administrador de bases de datos: instala, actualiza, respalda, protege y optimiza bases de datos.
DCL
Lenguaje de control de datos: concede o revoca permisos.
DDL
Lenguaje de definición de datos: crea y modifica la estructura de los objetos (CREATE, ALTER, DROP, TRUNCATE).
DML
Lenguaje de manipulación de datos: consulta y cambia filas (SELECT, INSERT, UPDATE, DELETE).
Elastic Pool
Grupo de bases de Azure SQL que comparten recursos para costos predecibles con cargas variables.
ELT
Extrae, carga y transforma dentro del almacén de destino (debe ser potente).
ETL
Extrae, transforma en un motor aparte y luego carga en el destino.
Familia de columnas
Columnas agrupadas que pueden variar por fila; Cassandra API.
Firewall de base de datos
Reglas que permiten IPs a nivel de servidor o de base de datos (sp_set_database_firewall_rule).
Grafo
Nodos (entidades) y aristas (relaciones) para analizar relaciones complejas; Gremlin API.
Gráfico de cascada
Muestra cómo se acumula un total con aumentos y disminuciones.
Gráficos de barras/líneas/circular
Barras: comparar categorías. Líneas: tendencias. Circular: partes de un todo. Dispersión: relación entre medidas.
HDInsight
Clústeres administrados de Hadoop, Spark, Kafka y Storm.
Informe
Una o más páginas de visualizaciones interactivas sobre un dataset.
Informe paginado
Informe con formato de página para imprimir; se crea con Power BI Report Builder.
Ingeniero de datos
Construye pipelines de ingesta y transformación y mantiene almacenes de datos.
JSON
Formato de texto semiestructurado con pares clave-valor y arrays; base de las bases de documentos.
Key Influencers
Visual que muestra los factores que más influyen en un resultado.
Microsoft Entra ID
Antes Azure AD; autenticación centralizada que admite MFA.
MPP
Procesamiento masivamente paralelo: el nodo de control distribuye el trabajo entre nodos de cómputo.
MySQL / MariaDB
Servicios PaaS open source de Azure para MySQL y MariaDB.
Nivel Archive
El más barato para datos rara vez usados; requiere rehidratación (horas).
Niveles de consistencia
De más fuerte a más débil: Strong, Bounded staleness, Session, Consistent prefix, Eventual.
OLAP
Procesamiento analítico: consultas complejas y agregaciones sobre datos históricos, desnormalizados, mayormente lectura.
OLTP
Procesamiento de transacciones: muchas operaciones pequeñas de lectura/escritura, normalizado y ACID.
PaaS / IaaS / SaaS
IaaS: tú gestionas SO y software. PaaS: el proveedor gestiona plataforma (parches, backups). SaaS: software listo para usar.
Pausar SQL pool
Pausar un pool dedicado detiene el cobro de cómputo y conserva los datos.
PolyBase / COPY
Cargan datos masivamente en Synapse (parte de ELT).
PostgreSQL / psql
Azure Database for PostgreSQL; psql es su cliente de línea de comandos y pgAdmin su herramienta gráfica.
Power BI Desktop
Aplicación para conectar datos, modelarlos y crear informes.
Procedimiento almacenado
Código SQL guardado en la base de datos que se ejecuta bajo demanda.
Procesamiento en streaming
Procesa cada evento al llegar, casi en tiempo real, con baja latencia.
Procesamiento por lotes
Procesa datos acumulados juntos en intervalos; se acepta latencia.
Redundancia de almacenamiento
LRS/ZRS replican en una región; GRS y RA-GRS (lectura secundaria) replican a otra región.
Replicación multirregión
Replica Cosmos DB en varias regiones: baja latencia global y resiliencia si cae una región.
Réplica de solo lectura
Copia de la base para descargar reportes sin afectar la carga transaccional.
Servicio Power BI
Plataforma en la nube para publicar, crear dashboards, compartir y programar actualizaciones.
SQL Managed Instance
PaaS casi 100% compatible con SQL Server (linked servers, SQL Agent, Database Mail); ideal para migrar.
SQL Server en VM
IaaS: control total del sistema operativo y de SQL Server.
Table API vs Table Storage
La Table API de Cosmos DB añade escrituras multirregión, menor latencia e indexación automática sobre Table Storage.
TDE
Cifra la base de datos, logs y backups en reposo.
Throughput (RU/s)
Capacidad provisionada en Cosmos DB; se configura a nivel de base de datos o de contenedor.
Tile
Una visualización anclada a un dashboard.
Treemap
Rectángulos anidados proporcionales; muestra proporciones de muchas categorías.
U-SQL / Data Lake Analytics
Servicio retirado de trabajos analíticos que usaba el lenguaje U-SQL.
Vista
Tabla virtual cuyo contenido lo define una consulta; puede basarse en varias tablas u otras vistas.
Wrangling / transformación
Transformar y mapear datos sin procesar a un formato útil para análisis.
Índice
Estructura que acelera búsquedas a costa de escrituras más lentas y más espacio; una tabla puede tener varios.
